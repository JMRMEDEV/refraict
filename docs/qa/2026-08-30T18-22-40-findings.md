## Resolution status

Findings below are marked `[FIXED]` where they have been addressed in the source,
pursuant to the priority list in the "Priority" section at the bottom.

### `[FIXED]` — C1 Repaired coordinates + C2 synthesized IDs + C3 per-stage timings
- Added `internal/cli/repair.go`: `repairComponent` now synthesizes IDs when the
  VLM omits them (`cropID-index`) and recovers empty/zero bounding boxes via OCR
  text-token fallback, then the enclosing crop's global box, clamping to bounds.
  Components with no recoverable box are dropped (counted) rather than poisoning output.
- `analyze.go` crop loop now routes components through `repairComponent`; the

- `stage("…")` now records genuine per-stage durations into a `stageTimes` map;
  `page.json` `meta.stages` reflects per-stage ms instead of copy-pasted total elapsed.

- B1: `cache status`/`cache clear` now resolve the cache location from config the

- B4: `reconstruct` now reports the actual `json.Unmarshal` error.

## Summary

The architecture is clean and package boundaries (`ir`, `model`, `crop`, `dub`, `graph`, `summarize`, `cache`) are well-designed. Unit tests pass. However, the pipeline's flagship output — the canonical component IR, measured colors, and relationship graph — is effectively broken end-to-end because VLM components arrive without IDs or coordinates and nothing repairs or validates them. Several documented features (cloud escalation, aggregator stage, adaptive text-height cropping, concurrency, benchmark region counts) are scaffolded but not wired in.

**Highest-leverage fixes:** (1) validate/repair component coordinates + synthesize IDs, (2) unify the cache path across commands, (3) add a golden-file integration test so all-null output cannot ship silently.

## Critical issues (produce wrong or empty output)

### C1 — Vision components never get IDs or global coordinates; the component pipeline collapses
In `e2e-test/results/crops/c0001.json`, every component has `"id": ""` and `"bbox_global": {0,0,0,0}`. The VLM returns text but no usable coordinates. This cascades:
- `dub.Reconcile` drops every component because `c.BBox.Empty()` is true (`X0 >= X1`).
- Result: `merged_components.json` is `null`, `colors.json` is `null`, and `page.json` has `"components": null`, `"colors": null`, `"relationships_elements": null`.

The "canonical UI IR" — described in the README as *"the key reusable artifact"* — comes out empty on a real run. The deterministic-measurement half of the value proposition (component boxes, measured colors, relationship graph, DOM) is non-functional end-to-end. There is no fallback to OCR token boxes and no crop-local coordinate assumption to compensate.

**Files:** `internal/cli/analyze.go` (crop ingest loop), `internal/dub/dub.go` (`Reconcile`).

### C2 — Empty component IDs break merging and the graph even when boxes exist
`graph.Build` and `probableDOM` key on `c.ID`, but crop components are copied with `comp.ID`, which is `""`. Relationships would reference empty-string nodes. IDs should be synthesized (e.g. `cropID + index`) during ingestion.

**Files:** `internal/cli/analyze.go`, `internal/graph/graph.go`, `internal/cli/helpers.go` (`probableDOM`).

### C3 — `page.json` stage timings are copy-paste duplicates
```go
"stages": map[string]int64{
    "ocr":    msSince(start),   // both report total elapsed
    "vision": msSince(start),
},
```
Both report cumulative time-since-start (528813 ms each in the e2e output), not per-stage durations.

**File:** `internal/cli/analyze.go`.

## Correctness / consistency bugs

### B1 — Cache path is inconsistent between commands
- `analyze` writes the cache to `resolveCacheDB(cfg.Cache.Database)` → `./refraict-cache.sqlite/refraict-files`.
- `cache status` / `cache clear` hardcode `./.refraict-cache` and ignore config.

`cache status` will report 0 entries / clear nothing while `analyze` populates a different directory. The repo shows both directories existing, confirming the split.

**Files:** `internal/cli/analyze.go` (`resolveCacheDB`), `internal/cli/cache_cmd.go`.

### B2 — Misleading naming: `refraict-cache.sqlite` is a directory of JSON files, not SQLite
The cache is a file-based JSON store (`cache.go`), yet the default path is `./refraict-cache.sqlite` and the package doc claims *"SQLite is available for indexed metadata."* No SQLite is used anywhere.

**Files:** `internal/cache/cache.go`, `internal/config/config.go`.

### B3 — `Component.Role` has an ineffective `omitempty` tag and is never populated
```go
Role ConstString `json:"role,omitempty"`  // omitempty has no effect on a non-pointer struct
```
Every serialized component would carry an empty `"role": {"value":"","source":"","confidence":0}`. Should be `*ConstString`. Currently masked only because components are null (C1).

**File:** `internal/ir/types.go`.

### B4 — `reconstruct` error handling bug
```go
if json.Unmarshal(data, &comps) != nil {
    return fail("parse components: %w", err)  // err is nil here; wrong variable
}
```
The unmarshal error is discarded and a nil error is wrapped.

**File:** `internal/cli/commands.go`.

### B5 — `benchmark` region count is a stub
README says benchmark reports *"geometry and region counts per file."* `cropPlanOnly` always returns exactly 1 region regardless of image, so `regions=1` for every file. It does not call the real crop planner.

**File:** `internal/cli/benchmark.go`.

### B6 — `min-text-height` and `DetailLongSide` configured but unused
`MinimumTextHeightAfter` and `NeedsSubdivision` / `MedianTextHeight` exist in `crop/plan.go`, but `SubdivideRegion` never calls them — subdivision is purely size-based, ignoring text legibility, which is the stated rationale for adaptive cropping. `DetailLongSide` is never read anywhere.

**Files:** `internal/crop/plan.go`, `internal/config/config.go`.

### B7 — `--adaptive=false` path carries a dead overview crop
The non-adaptive branch injects a synthetic `{ID:"ov"}` crop then appends `PlanFixed`, but the `ov` crop is always `continue`-skipped in the analyze loop. Works, but is dead weight in both paths.

**File:** `internal/cli/analyze.go`.

## README vs. implementation mismatches

- **M1 — OCR setup is undocumented.** The README FAQ says OCR "shells out to an OCR engine configured via the environment/backend" but never mentions the actual mechanism: the `REFRAICT_OCR_CMD` / `REFRAICT_OCR_ARGS` environment variables (`internal/cli/helpers.go`). Users cannot enable OCR from the README alone.
- **M2 — Cloud escalation is documented but not implemented.** The `escalate` package defines `Signal` / `Policy` / `NeedsEscalation`, and config has a full `cloud` section, but `analyze` never calls the escalation logic and there is no cloud backend. `--cloud-fallback` only flips config flags that nothing consumes.
- **M3 — `reconciler.confidence_merge` is configured but never used** (merge uses area-weighting, not this threshold).
- **M4 — `aggregator` model is configured and shown in provenance but never invoked.** There is no global-reasoning stage that uses it. In the e2e config all three roles point at the same `qwen3-vl:8b`.
- **M5 — `page.json` `meta.stages` advertises per-stage timings it does not actually produce** (see C3).

## Gaps / opportunity areas

- **G1 — No coordinate validation or repair.** Highest-impact fix: after the VLM returns, clamp boxes to crop bounds, reject zero-area boxes, and fall back to OCR token boxes when the model omits coordinates. This alone would make `page.json` non-empty.
- **G2 — `schema_failed` is not triggered on empty-coordinate output.** The model returned parseable JSON with useless coordinates, so no repair/escalation fired. Quality signals should include "components without valid boxes."
- **G3 — No integration test on real output.** Unit tests are solid per-package, but nothing asserts that a full `analyze` run yields non-null components. The committed e2e results (all-null) are exactly the regression a golden-file test would catch.
- **G4 — `workers` / `batch_size` are config-only; crops are processed serially** in a single loop. Concurrency is described but not implemented.
- **G5 — No `.gitignore`.** The repo has committed the built `refraict` binary (~10 MB), the cache directories, and `.libreq/` session artifacts — these should not be tracked.
- **G6 — `ORCToken` is a typo of "OCRToken"** baked into the public IR type and JSON. Worth fixing before the schema is depended upon.
- **G7 — Model-based graph inference is defined but unused.** `BuildGraphPrompt` / `UIGraphV1` prompts exist, but the graph is built purely from geometry and DOM is geometry-only heuristic.
- **G8 — Errors are widely swallowed with `_ =`** (e.g. every `ws.WriteJSON` in `analyze`), so a failed write during `analyze` is invisible.
- **G9 — The `internal/migrate` package is empty** (no source files).
